# Data migration

## What was migrated

The specification assumed configuration was stored in Firebase. The audit found **no Firebase usage anywhere** in the repository or in the Vercel project's environment variables (see [AUDIT.md](AUDIT.md)). The source data was the content hardcoded in the old React components, so the migration moves that content into Postgres.

| Source (old component) | Target table | Records | Treatment |
| --- | --- | --- | --- |
| `index.html` title/description | `site_settings`, `pages.home` | 1 | Carried over verbatim |
| Page headings and intros | `pages` | 6 | Carried over verbatim |
| Navbar / Footer links | `nav_links` | 10 | Carried over |
| `Books.tsx`: 3 named books | `books` | 3 | Published, prices and availability preserved |
| `Home.tsx`: "To Kill a Mockingbird" (featured on the homepage but missing from the catalog) | `books` | 1 | Published without price, category or description |
| `Books.tsx`: "Sample Book 1–15" | — | 0 | **Not migrated.** Generated by `Array.from()` as demo filler |
| `CafeMenu.tsx` | `menu_items` | 11 | Published, prices preserved |
| `Events.tsx`: Poetry Night, Coffee Brewing Workshop | `events` | 2 | **Imported unpublished.** Dates have passed and details are unverified; the garbled workshop description was reduced to its readable part |
| `Events.tsx`: "Community Event 1–15" | — | 0 | **Not migrated.** Generated demo filler |
| `About.tsx` team member | `team_members` | 1 | Published; the broken placeholder photo URL was dropped |
| `Cart.tsx` coupon `SAVE10` | `coupons` | 1 | Active, 10 % |

The data lives in [`scripts/seed-data.ts`](../scripts/seed-data.ts); [`scripts/seed.ts`](../scripts/seed.ts) only fills empty tables, so re-running it never overwrites edits or resurrects deleted records.

## Production procedure

On Vercel, steps 3 to 6 run automatically during the build when `RUN_MIGRATIONS_ON_BUILD=1` is set, with the owner account created from the `ADMIN_BOOTSTRAP_*` variables (see [DEPLOYMENT.md](DEPLOYMENT.md#first-time-setup)). To run them by hand instead, use a trusted machine with the production `DATABASE_URL_UNPOOLED` loaded (for example via `vercel env pull .env.production.local` and exporting it). Nothing here touches the existing live site until step 6.

1. **Create the database.** Add Neon from the Vercel Marketplace to the `booksncafe` project (see [DEPLOYMENT.md](DEPLOYMENT.md)).
2. **Back up first.** Even on a fresh database, take a Neon snapshot from the console. For later runs, `npm run db:backup` writes a JSON snapshot of all content to `./backups/`.
3. **Apply the schema.** `npm run db:migrate`
4. **Import content.** `npm run db:seed`, which prints the number of rows inserted per table. Expected on an empty database: settings 1, nav 10, pages 6, books 4, menu 11, events 2, team 1, coupons 1.
5. **Create the owner account.** `npm run admin:create -- --email <owner email> --role admin --name "<name>"` (prompts for a password of at least 12 characters).
6. **Verify.** `npm run db:verify` checks row counts, representative records (e.g. the Espresso price), required fields, relationships and that an active admin exists. Do not deploy if any check fails.
7. **Deploy.** Merge the PR (or promote the preview). Then spot-check `/`, `/books/1984`, `/menu`, `/sitemap.xml` and sign in to `/admin`.

## Rollback

- **Application:** the previous Vite deployment stays in Vercel's deployment history. Use *Instant Rollback* (Vercel → Deployments → previous production deployment → Promote) to restore it within seconds. It has no database dependency.
- **Data:** Neon point-in-time restore covers the last 6 hours on the Free plan; restore to a new branch, verify, then switch. JSON snapshots from `npm run db:backup` give a human-readable copy that is independent of Neon.
- **Schema:** migrations are forward-only. To undo a migration, restore a pre-migration branch rather than editing applied files.

No source data is destroyed by this migration: the original content remains in git history (commit `1ef498d`), and Firebase was never involved.
